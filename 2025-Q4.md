- [Introducing Optimized Compaction in Fabric Spark](https://blog.fabric.microsoft.com/en-us/blog/announcing-optimized-compaction-in-fabric-spark)
  
  Summary:

    1. **Auto Compaction** prevents small file accumulation without dedicated maintenance jobs.
    2. **Fast Optimize** makes your ad-hoc or scheduled OPTIMIZE operations complete quickly by avoiding suboptimal compaction work.
    3. **File Level Compaction Target** prevents redundant work when you adjust optimization strategies over time.

  - Enable **Fast Optimize** at session level (Runtime 1.3):

    ```python
    spark.conf.set('spark.microsoft.delta.optimize.fast.enabled', True)
    ```

    > Determine what files need to be optimized

  - Enable **File Level Compaction Target** at session level (Runtime 1.3):

    ```python
    spark.conf.set('spark.microsoft.delta.optimize.fileLevelTarget.enabled', True)
    ```

    > Avoid unnecessary file compaction
  
  - Enable **Auto-compaction** at session level or table level (Runtime 1.3):

    ```python
    spark.conf.set('spark.databricks.delta.autoCompact.enabled', True)
    ```

    ```sql
    CREATE TABLE dbo.ac_enabled_table
    TBLPROPERTIES ('delta.autoOptimize.autoCompact' = 'true')
    
    ALTER TABLE dbo.ac_enabled_table
    SET TBLPROPERTIES ('delta.autoOptimize.autoCompact' = 'true')
    ```

    > Automatically optimize the tables if needed after each write operation

- [Spark Connector for SQL databases (Preview)](https://blog.fabric.microsoft.com/en-us/blog/spark-connector-for-sql-databases-preview)

  Read and **write** data in SQL databases (Azure SQL Db, Azure SQL MI, Fabric SQL Db, SQL Server in AzWM)
  
  Sample code ([source](https://learn.microsoft.com/en-gb/fabric/data-engineering/spark-sql-connector?tabs=pyspark%2Caccesstoken)):

  ```python
  import com.microsoft.sqlserver.jdbc.spark
  url = "jdbc:sqlserver://<server>:<port>;database=<database>;"
  row_data = [("Alice", 1),("Bob", 2),("Charlie", 3)]
  column_header = ["Name", "Age"]
  df = spark.createDataFrame(row_data, column_header)
  df.write.mode("overwrite").option("url", url).mssql("dbo.publicExample")
  spark.read.option("url", url).mssql("dbo.publicExample").show()
  
  url = "jdbc:sqlserver://<server>:<port>;database=<database2>;" # different database
  df.write.mode("overwrite").option("url", url).mssql("dbo.tableInDatabase2") # default url is updated
  spark.read.mssql("dbo.tableInDatabase2").show() # no url option specified and will use database2
  ```

- [OPENROWSET and External Tables for Fabric SQL Databases (Preview)](https://blog.fabric.microsoft.com/en-us/blog/openrowset-and-external-tables-for-fabric-sql-databases)

  Select with `OPENROWSET`:

  ```sql
  SELECT TOP 100 * FROM OPENROWSET
   (BULK 'abfss://<workspaceID>@<tenant>.dfs.fabric.microsoft.com/<lakehouseid>/Files/contoso/store.parquet', FORMAT = 'parquet' )
   AS STORE;
  ```

  Create a `DATA SOURCE`:

  ```sql
  CREATE EXTERNAL DATA SOURCE [Cold_Lake] WITH (
  LOCATION = ' abfss://<workspaceID>@<tenant>.dfs.fabric.microsoft.com/<lakehouseid>/Files/');
  
  -- Parse the JSON data
  SELECT *
  FROM OPENROWSET(
      BULK 'JSON/sample_user_profile.json'
      ,DATA_SOURCE = 'Cold_Lake'
      ,SINGLE_CLOB
  ) AS JSONData
  CROSS APPLY OPENJSON(JSONData.BulkColumn);
  ```

  Use a `DATA SOURCE` and create `FILE FORMAT` and `EXTERNAL TABLE`:

  ```sql
  CREATE EXTERNAL FILE FORMAT Parquetff WITH (FORMAT_TYPE=PARQUET);
  
  CREATE EXTERNAL TABLE [ext_product](
      [ProductKey] [int] NULL,
      [ProductCode] [nvarchar](255) NULL,
  ```
